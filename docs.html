Core idea

Stars2Cells (S2C) matches neurons across sessions by leveraging local geometric structure (constellations) instead of a single global alignment. Quads are sampled across scales, hashed into invariant signatures, and used to propose correspondences that are verified via local transform hypotheses.

One framing that helps: robusto (robust) to local non-linearities, because S2C does not rely on a single transform for the entire field of view.

Inputs and outputs

Inputs

Stars2Cells currently operates on centroid-based neuron representations. Each imaging session must be provided as a single .npy file containing a Python dictionary saved with allow_pickle=True.

  • File naming: {animal_id}_{session_id}.npy (numeric IDs only)
  • Required keys: centroids_x, centroids_y, roi_ids, subject_id, session_id
  • Centroids: pixel coordinates (float or int), equal-length arrays
  • Minimum size: ≥ 4 neurons per session (smaller sessions are skipped)
  • Directory layout: all session files placed in a single input directory

Additional fields (e.g. footprints, traces, timestamps, shape descriptors) are permitidos (permitted) but ignored by the pipeline.

Outputs

Cross-session match registry with confidence scores, plus QC summaries and optional diagnostic plots.

  • Match list / registry: stable IDs across sessions
  • Confidence: per-match quality or score
  • QC summaries: residual distributions, outlier maps, match density
  • Optional plots: alignment diagnostics, mismatch heatmaps

Environment

This early release is tested against the following versions (Python 3.11.14):

matplotlib==3.10.8 numpy==2.4.0 psutil==7.0.0 PyQt5==5.15.11 pyqtgraph==0.14.0 scipy==1.16.3

Note: there is currently no example data packaged with the repo, so the UI and pipeline are intended to be run on your own session exports.

Pseudo-pipeline

1) Extract ROIs / centroids 2) Draw quads across multiple size scales 3) Hash quads into invariant signatures 4) Retrieve candidate correspondences via hash matches 5) Generate local transform hypotheses 6) Verify via reprojection + descriptor filtering 7) Consensus selection + registry construction 8) QC: match density, residual errors, outlier maps
